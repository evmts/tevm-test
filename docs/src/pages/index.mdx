## What is Tevm Test?

Tevm Test is the standalone home for Tevm's testing libraries. It publishes three packages:

| Package | What it gives you |
| --- | --- |
| [`@tevm/test-matchers`](/api/test-matchers) | Vitest matchers for emitted events, reverts and custom errors, ETH and ERC20 balance deltas, account state, and contract calls |
| [`@tevm/test-node`](/api/test-node) | A Tevm node, client, and transport that record forked JSON-RPC responses to disk so fork tests are deterministic and run offline |
| [`@tevm/test-utils`](/api/test-utils) | Precompiled Solidity fixtures (`SimpleContract`, `ErrorContract`, ERC20/ERC721, …) and RPC helpers |

## Why it exists

Solidity contracts are usually tested in Solidity, in a second toolchain, with a second set of assertions.
That works, but the code that *calls* your contracts — the frontend, the indexer, the SDK — is TypeScript,
and its tests are Vitest. Tevm Test lets that TypeScript suite make the same assertions Foundry makes:

<div className="tevm-code-frame">

```ts
import { SimpleContract } from '@tevm/test-utils'
import { createMemoryClient } from '@tevm/memory-client'
import { expect, test } from 'vitest'

const client = createMemoryClient()

test('set() emits ValueSet', async () => {
  const { createdAddress } = await client.tevmDeploy({
    ...SimpleContract.deploy(0n),
    addToBlockchain: true,
  })
  const contract = SimpleContract.withAddress(createdAddress!)

  await expect(client.tevmContract(contract.write.set(100n)))
    .toEmit(contract, 'ValueSet')
    .withEventArgs(100n)
})
```

</div>

No RPC endpoint, no anvil process, no separate assertion language.

## Three things that are hard elsewhere

<div className="tevm-features">
  <div className="tevm-feature">
    <p className="tevm-feature-title">Balance deltas</p>
    <p className="tevm-feature-body">
      <code>toChangeBalance</code> replays your transaction under a <code>prestateTracer</code> and diffs the
      pre/post state, so you get exact wei deltas including gas — and the same works for ERC20 balances, where
      the token's storage slot is discovered automatically rather than hardcoded.
    </p>
  </div>
  <div className="tevm-feature">
    <p className="tevm-feature-title">Custom errors with arguments</p>
    <p className="tevm-feature-body">
      <code>toBeRevertedWithError(client, contract, 'InsufficientBalance').withErrorArgs(50n, 1000n)</code>
      decodes the revert data against your ABI, with full type inference on the argument tuple.
    </p>
  </div>
  <div className="tevm-feature">
    <p className="tevm-feature-title">Forked tests that don't flake</p>
    <p className="tevm-feature-body">
      <code>createTestSnapshotNode</code> writes every upstream JSON-RPC response into
      <code>__rpc_snapshots__/&lt;test file&gt;.snap.json</code> next to your test. Commit it, and CI never
      touches the network again.
    </p>
  </div>
</div>
